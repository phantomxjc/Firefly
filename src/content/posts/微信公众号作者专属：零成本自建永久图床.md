## 01 · 缘起

如果你写过公众号，下面这些场景一定不陌生：

1. **素材库卡到怀疑人生**：图片越堆越多，打开一篇文章要加载 20 秒
2. **换电脑就找不回原图**：历史文章的配图找不到，改文章只能重新配图
3. **第三方图床突然全挂**：某天起床发现所有外链失效，文章集体"失明"
4. **笔记软件图片同步失败**：Obsidian / Typora 笔记想一键发公众号，图片总是出问题

> 💡 核心公式：自建图床 = 自己的域名 + 免费云存储。外链永久有效、微信不拦截、全球加载快。
>
> 📋 阅读指南：预计 8 分钟 | 上手 30 分钟 | 成本 0 元

## 02 · 准备

| 工具 | 作用 | 备注 |
|---|---|---|
| Cloudflare 账号 | 托管 Pages + 存储 | 免费，注册即用 |

## 04 · 部署

登录 Cloudflare → Workers & Pages → 创建 → Pages → 连接 Git → 选你 Fork 的仓库。

⚠️ 下面配置**一字不差照抄**，错一个字段都可能部署失败：

| 配置项 | 正确值 | 常见错误 |
|---|---|---|
| 框架预设 | None | 误选 React / Vue |
| 根目录 | / | 改成 functions 或 frontend |
| 构建命令 | npm install | npm run build |
| 构建输出目录 | /frontend-dist | /dist 或 /build |
| Node.js 版本 | 22.x | 低于 18.x 可能报错 |

点"保存并部署"后第一次会**部署失败**——这是正常的，因为还没绑定存储，继续下一步即可。

## 05 · 绑定

这一步最关键，进 Pages 项目 → 设置 → 绑定，添加 **2 条必填绑定**：

**① KV — 存后台配置**

| 字段 | 正确值 |
|---|---|
| 变量名 | `KV`（代码读 env.KV，别写成别的） |
| 类型 | KV Namespace |
| 命名空间 | `img_url` |

**② R2 — 公众号主力存储（免费 10GB）**

| 字段 | 正确值 |
|---|---|
| 变量名 | `img_r2`（必须是这个，代码读 env.img_r2） |
| 类型 | R2 Bucket |
| 存储桶 | `img_r2` |

> ⚠️ 绑定完成后，务必返回"部署记录"→ 最新那条 → 点击"重试部署"。不重部署，绑定不会生效！

## 06 · 域名

让图片用你自己的域名访问，而不是 Cloudflare 的随机域名：

1. **Pages 侧挂域名**：Pages → 项目 → 自定义域 → 填 `img.yourname.com`，CF 会自动加 DNS 记录
2. **R2 侧开公共访问**：CF → R2 → 你的桶 → 设置 → 公共访问 → 启用，复制 `https://xxx.r2.dev`（不开公共访问，图片会返回 403！）
3. **后台配置 R2 渠道**：访问 `https://img.yourname.com/dashboard` → 系统设置 → 上传设置 → 添加渠道 → R2，填桶名 + 公共访问链接，启用

## 07 · 技巧

**技巧 1：配 PicGo 一键传图。** PicGo 插件市场搜 `cf-imgbed`，配置域名 `https://img.yourname.com`、上传路径 `/upload`。

- 以前：截图 → 保存本地 → 上传公众号后台 → 复制地址（30 秒）
- 现在：截图 → Ctrl+Shift+P → 自动出外链直接粘贴（3 秒）

**技巧 2：图片命名规范。** 后台开启"时间戳重命名"，文件自动变成 `1782889518764_图片名.png`，不冲突又能一眼看出归属。

**技巧 3：备份策略。** R2 主力（免费 10GB，够用 5-10 年）+ Telegram 兜底渠道，R2 满了自动切 TG，永不丢图。

## 08 · 避坑

| 问题 | 原因 | 解决 |
|---|---|---|
| 部署报 `frontend-dist not found` | 构建输出目录没填 `/frontend-dist` | 回去改配置 |
| 上传失败 `R2_BUCKET_NOT_FOUND` | R2 绑定变量名不是 `img_r2` | 改名并重部署 |
| 图片 403 打不开 | R2 没开公共访问 | 桶设置里启用 |
| 后台进不去 | KV 没绑或变量名错 | 确认变量名是 `KV` |
| 部署一直失败 | 绑定后没重部署 | 部署记录 → 重试部署 |
