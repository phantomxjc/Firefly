手里养着几个小网站、NAS 上一堆 Docker 服务，最怕什么？不是流量暴增，是哪天悄悄挂了你还不知道。等朋友截图发过来"你的站打不开了"，那感觉跟被老师当众点名差不多。

之前我都是用第三方的监控服务，免费版限制一堆，HTTP 监控只能加几个，超过就要付费。后来索性在自己飞牛NAS上部署了 Uptime Kuma，一个开源的自托管监控面板，状态页、告警通知、历史图表全都有，还不限监控数量。用了两个多月，今天把这套东西分享给大家。

## 01 Uptime Kuma 是个啥

一句话概括：一个跑在你自己机器上的"网站体检医生"。

它是 GitHub 上 60 多万 Star 的明星项目，界面做得相当漂亮，深色科技风，每次打开都有点 NASA 控制中心的既视感。支持的监控类型挺全：

- HTTP/HTTPS 网站监控（最常用）
- TCP 端口监控（看某个服务端口通不通）
- Ping 监控（检测设备是否在线）
- DNS 记录监控
- Docker 容器监控（对！能直接盯 NAS 上的容器）
- 关键词监控（检查网页里有没有出现特定文字）

每个监控项都有响应时间曲线、历史可用率，挂了的时候状态点会从绿色变红，一眼就能看到。

## 02 飞牛NAS上部署：五分钟搞定

飞牛NAS的 Docker 应用部署体验做得不错，我们直接用图形界面来，不用碰命令行。

**第一步：打开 Docker 管理器**

进飞牛OS后台，找到 Docker 应用，切到"镜像"那个标签，搜索 `louislam/uptime-kuma`，下载 latest 标签。镜像大概 600MB 左右，看网速，喝口茶的功夫就好。

**第二步：创建容器**

下载完点"运行"，配置很简单，就三项关键设置：

1. **端口映射**：容器端口 3001 映射到本地一个空闲端口，比如 3001
2. **卷挂载**：新建一个文件夹比如 `/vol1/1000/docker/uptime-kuma`，挂载到容器的 `/app/data`，这样配置和监控历史才不会丢
3. **重启策略**：选"除非手动停止否则总是重启"，保证断电重启后自动拉起来

点确认，等几十秒，浏览器访问 `http://NAS的IP:3001`，就能看到初始化界面了。

**第三步：创建管理员账号**

第一次进会让你设置用户名和密码，设个强一点的，毕竟这玩意能看到你所有服务的健康状况。

## 03 添加监控项 + 配置告警通知

部署完只是开始，关键是把该盯的东西都加进来。

**加监控**：点左上角"添加监控项"，类型选 HTTP(s)，URL 填你的网站地址，心跳间隔默认 60 秒就挺合适。我这里把博客、图床、几个 Docker 服务都加上了一下子。

**配通知**：这是 Uptime Kuma 最好用的部分。右上角头像 → 设置 → 通知，支持的通知方式多到离谱：Telegram Bot、企业微信、钉钉、飞书、Server酱、Bark、邮件、Webhook……基本上国内能用的都覆盖了。

我自己用的是 Server酱 Turbo 版，往微信公众号推消息。配置很简单，拿到 SendKey 填进去，点"测试"，微信秒收到。之后再挂这个通知方式到所有监控项上，任何服务一挂，微信立刻响。

## 04 一些我踩过的坑

**关于时区**：默认容器里时区是 UTC，图表时间会差 8 小时。启动容器时加个环境变量 `TZ=Asia/Shanghai` 就行，或者进容器手动改。

**关于 Docker 容器监控**：想监控飞牛NAS自己跑的 Docker 容器时，要把 `/var/run/docker.sock` 挂载进容器里，注意这给容器的权限比较大，自己用没事，别对外开放就行。

**关于反向代理**：如果想用域名访问监控面板，前面套个 Nginx Proxy Manager 就行，记得开 WebSocket 支持，不然界面会转圈。

**关于备份**：所有数据都在挂载的那个文件夹里，定期用飞牛自己的快照功能备一下，几乎零成本。
